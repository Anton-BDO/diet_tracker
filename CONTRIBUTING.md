# Как работаем с репозиторием

## Ветки

Напрямую в `main` не пушим, она защищена. Каждая задача из Jira делается
в своей ветке от свежего `main`.

```
feature/DIET-12-router      новая функциональность
fix/DIET-30-streak-reset    исправление ошибки
docs/DIET-5-readme          документация
```

Вместо `DIET` ключ нашего проекта в Jira.

## Коммиты

Начинаем с ключа задачи, дальше коротко что сделано:

```
DIET-12: добавить роутер с параметрами пути
```

Jira сама подтянет коммиты и PR к задаче, если в них есть ключ.

## Порядок работы

```bash
git checkout main
git pull
git checkout -b feature/DIET-12-router
# пишем код и тесты
flake8 backend tests scripts
pytest
git add .
git commit -m "DIET-12: добавить роутер"
git push -u origin feature/DIET-12-router
```

Потом на GitHub открываем Pull Request в `main` и заполняем шаблон.

## Правила для PR

1. Один PR на одну задачу, лучше небольшой.
2. CI должен быть зелёным: flake8 и pytest с покрытием от 80%.
3. Нужно одно одобрение ревьюера, обычно тимлида.
4. Мержим через Squash and merge, ветку после мержа удаляем.
5. Если поменялся формат API, в том же PR обновляем `docs/openapi.yaml`.

## Стиль кода

PEP8, длина строки до 79 символов. Перед коммитом запускаем `flake8`.
Сторонние библиотеки добавляем только после согласования с преподавателем.
